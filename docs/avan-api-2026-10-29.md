# 卡台 API 文档变更分析：2026-10-28 → 2026-10-29

对比 `avanfinity-openapi (5).json` 和 `(6).json`。文档版本号没变（仍是 2026-10-28），接口路径没有增删，只改了一处：

| 变化 | 位置 | 说明 |
|---|---|---|
| **GPT CDK 支持点数（Credits）** | `POST /gpt-direct/cdks/generate`、`CdkGenerateInput.plan` | `plan` 从订阅枚举（go / plus / pro_5x / pro_20x / pro_25x）改成正则：订阅套餐，或 `credits_N`。固定面额 `credits_250 / 1000 / 2500 / 5000`，自定义 N 为 250–9999999 的整数（不能有前导零） |

接口说明里补充的规则：

- 点数 CDK **生成免费**，兑换时按所选地区**当时的点数报价**扣费、充值到账号，**不改变订阅**
- 点数和结账地区在**生成时固定**，兑换时不能改
- 点数 CDK **只支持「自有 OpenAI 支付服务」**，也就是用本账户生成的 CDK（`/gpt-direct/cdks/generate`），平台库存里买的 CDK 没有点数

上一版分析（`avan-api-2026-10-28.md`）里写的「CDK 生成接口没有 credits，点数只能直充」已经不成立。

## 我们的处理

同时决定 GPT 不再直接对接直充服务，统一走卡台 CDK（订阅和点数一样）：

- 去掉 GPT 直充：交付方式选项、资金护栏、直充下单和对账、人工核对；数据库迁移第 9 版删除 `direct_spend` 表、`redemptions.direct_task_id` 和护栏设置（还有没出结果的直充时拒绝升级）
- 点数：
  - 套餐目录加入四个固定面额，生成页和商品编辑支持自定义点数；格式校验和卡台一致
  - 只允许自有码策略（自有码在买家兑换时才向卡台生成 CDK，正好是「本账户生成」）；托管码策略生成或上架会被拒绝
  - 成本：点数没有 CDK 售价，按套餐目录（`/gpt-direct/plans` 里的点数面额：预期金额 + 服务费）估算；自定义点数按最接近的固定面额单价折算。价格保护也用这个估算
  - 「只允许 Free 账号」对点数不生效
  - 兑换页文案：「充值成功」，不显示自动续费

## 需要向卡台确认

1. 点数 CDK 兑换时如果点数报价比生成时高很多，会不会有上限保护？（订阅 CDK 有售价，点数没有，我们只能事后按估算比较）
2. `/gpt-direct/cdk-offers` 以后会不会返回点数的售价？返回的话我们会优先用它，不再估算
3. 「自有 OpenAI 支付服务」是否就是指本账户通过生成接口得到的 CDK？对 `forceNewCard`（每码独立支付）有没有限制？
