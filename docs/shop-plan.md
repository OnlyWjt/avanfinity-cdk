# 商城（发卡网）+ 支付 + 优惠券 + 代理分销 · 实施方案

## 背景
现在的流程是「管理员生成码 → 线下发给买家 → 买家在兑换页兑换」。要改成完整的发卡网：买家自助下单付款，系统自动发码，并支持优惠券和代理分销。

已确认的需求：
- 支付：易支付类聚合、USDT（TRC20）、支付宝官方、微信支付官方
- 交付：付款后显示兑换码 + 「立即兑换」按钮，进入现有兑换流程（兑换策略照常生效）
- 买家：免注册可下单；注册后可看全部订单、用余额付款
- 邮件：配置 SMTP，付款成功后把兑换码发到买家邮箱
- 代理：分站自定价、推广返佣、批发进货三种都要

## 页面
| 入口 | 说明 |
|---|---|
| `/shop/` | 商城首页：商品卡片 → 下单面板（数量、优惠券、邮箱、查询密码、支付方式） |
| `/shop/pay.html` | 支付页：跳转第三方 / 二维码 / USDT 地址 + 精确金额 + 倒计时，自动轮询到账 |
| `/shop/order.html` | 订单页：状态、兑换码（复制、立即兑换） |
| `/shop/query.html` | 订单查询：订单号或邮箱 + 查询密码；同一浏览器自动列出历史订单 |
| `/s/{slug}` | 代理分站：同一套商城，价格和店铺名用代理自己的设置 |
| `/account/` | 买家中心：登录 / 注册 / 找回密码、我的订单、余额充值、申请成为代理 |
| `/agent/` | 代理中心：收益、分站设置与定价、推广链接、批发进货、我的库存、提现 |
| 后台「商城」分组 | 商品、商城订单、优惠券、代理（等级 / 提现审核）、客户；设置页新增「支付」「邮件」 |

现有兑换页 `/` 保持不变；设置里可以把首页切换成商城。

## 关键规则
- 价格、优惠、库存全部由服务端计算；订单 15 分钟未付自动关闭，释放库存和优惠券
- 支付回调：验签 → 核对金额 → 按平台流水号幂等入账；后台定时主动查单，防回调丢失
- 发货复用 `generateBatch()`，幂等键 `order-订单号`，重复回调不会重复发码；卡台故障时自动重试，并支持后台补发
- 金额按「分」存整数，USDT 按 6 位小数整数存
- 分站利润 = 代理零售价 − 进货价；推广佣金 = 实付 × 等级佣金比例；分站订单不叠加佣金
- 代理收益先冻结 N 天（默认 3 天，防退款），之后可提现；提现由后台审核后线下打款
- 优惠券只用于主站零售订单，不能用于分站和批发
- 退款：后台标记退款（线下退款），未兑换的码自动撤销，冲回代理收益；一期不调用各渠道的退款接口

## 支付渠道（全部用 node:crypto 实现，不引 SDK）
- 易支付：标准协议，MD5 签名，回调回复 `success`
- USDT TRC20：固定地址 + 唯一金额尾数，每 15 秒查询 TronGrid 匹配入账，交易哈希唯一
- 支付宝：当面付二维码 + 网页支付，RSA2 签名验签，查单兜底
- 微信支付 v3：Native 二维码，请求签名 + 回调验签 + AES-GCM 解密，查单兜底
- 余额支付：注册买家用余额，原子扣减

## 分阶段交付
1. 核心闭环：商品、商城前台、下单、易支付、自动发货、订单页 / 查询、SMTP 邮件、后台订单
2. 其他支付：USDT、支付宝、微信、主动查单与超时关单
3. 买家账户：注册登录、余额与充值、余额支付、认领订单
4. 优惠券
5. 代理分销：等级、分站、推广、批发、收益冻结、提现
6. 整合：统计改用真实成交额、通知、文档
