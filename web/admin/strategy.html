能覆盖卡台的兑换策略吗？

大部分可以。做法是用户不直接去卡台兑换，而是先经过我们的兑换页和后端；后端检查完规则，再替用户去调卡台的接口。 每条规则都标了在哪一层执行： ${LAYER_OWN} 我们自己的后端执行，随时可改； ${LAYER_GEN} 生成兑换码时写进卡台，这批码之后就不能再改； ${LAYER_PLAT} 卡台强制执行，我们改不了，只能在它之上再加严。

托管码 简单
给用户的是卡台原始码 GPTD-XXXX…
用户 → 我们的兑换页 → 后端检查规则 → 卡台公开兑换接口
⚠ 卡台码本身就能兑换。用户如果直接去卡台官方兑换页兑，就绕过了我们的规则，所以只算「软控制」。
自有码 推荐
给用户的是我们自己生成的码 TB-XXXX…
用户 → 我们的兑换页 → 后端检查规则 → 当场向卡台生成 1 张码 → 后端替用户兑换
✓ 卡台码从来不会给到用户，规则不能绕过；还能做「失败自动重试」「人工审核后再兑」这类卡台没有的功能。
能力卡台自带我们能做到执行层
IP / 设备频率限制只有按 IP 的全局限流每个策略单独设置次数、时间窗、人机验证${LAYER_OWN}
有效期 / 兑换时段 / 地区无码的有效期、每天可兑时段、按国家拦截${LAYER_OWN}
同一账号兑换次数无预检会返回账号邮箱 / 用户名，按账号计数${LAYER_OWN}
只允许 Free 账号 / 邮箱域名黑白名单无根据预检结果判断${LAYER_OWN}
价格保护报价超过上限时直接失败实时报价比售价高多少就拦截 / 转人工 / 放行${LAYER_OWN}
失败后自动重试失败后码被释放，要用户自己再兑自有码模式下由后端自动重试 N 次${LAYER_OWN}
人工审核无命中规则先挂起，管理员通过后再提交卡台${LAYER_OWN}
每码独立支付 / 资金上限有生成时选择，写进这批码${LAYER_GEN}
报价有效期（GPT 24h、X/TG 30 分钟）有只能更严，不能延长${LAYER_PLAT}
每分钟最多 5 个新报价、一次性令牌、设备绑定有无法改变${LAYER_PLAT}
卡台风控、账号资格判定（如已是会员）有无法放行卡台拒绝的请求${LAYER_PLAT}

策略

兑换码按「码前缀 → 批次 → 默认」匹配策略；同时命中多个时，优先级数字小的生效。
